# 架構與驗收

## 權限

| 功能 | 全站管理員 | 空間編輯者 | 空間檢視者 | 未授權／未登入 |
|---|---|---|---|---|
| 公開工具示範 | 是 | 是 | 是 | 是 |
| 讀取空間及行程 | 全部 | 已授權 | 已授權 | 否 |
| 新增／編輯行程 | 是 | 是 | 否 | 否 |
| 刪除行程 | 是 | 否 | 否 | 否 |
| 建立空間／管理成員 | 是 | 否 | 否 | 否 |
| 建立管理員 | Firebase Console 專案權限 | 否 | 否 | 否 |

資料模型：

```text
users/{uid}                         { role: 'admin' }，僅受信任管理環境寫入
users/{uid}/spaces/{workspaceId}     { role: 'editor' | 'viewer' }
workspaces/{workspaceId}             { name, toolId: 'travel', createdAt }
workspaces/{workspaceId}/records/{id}
  { title, time, content, done, version, updatedAt, updatedBy }
```

成員索引就是授權來源，避免兩份成員清單不同步。一般會員只列出自己的 spaces，再逐一讀取已授權空間；不對全部 workspaces 作未受限查詢。全站管理員可列出全部空間。未建立 users 主文件仍可存在 spaces 子集合。

每個工作空間固定對應一個工具，記錄放在該空間的 records，不共用全站 records。V1 僅允許 travel；未來新增其他工具需同步加入工具型別、欄位驗證與權限測試，不能只丟入 HTML 就自動同步。

規則預設拒絕未知路徑，檢查欄位白名單、長度、時間格式、型別、修改者、伺服器時間及版本遞增。前端按鈕只提供操作引導，資料授權由 Firestore 強制執行。所有使用者文字以 textContent 呈現。

## 多人同步與衝突

- onSnapshot 逐筆接收同空間變更；在表單開啟時不覆蓋使用者草稿。
- 儲存時以交易重新讀取資料，版本與開啟時不同則拒絕儲存，保留草稿並提示合併。
- 同時建立示範資料採固定文件 ID 和單一交易，避免重複或覆寫。
- 登出／登入身分切換會清除畫面、關閉編輯器並解除舊監聽。
- 使用記憶體快取，不主動開啟持久離線資料庫。交易在離線時不能提交。
- 最後修改人與時間可查看；V1 沒有完整版本歷史、復原、游標協作或逐字共同編輯。
- 工作空間改名、刪除與檔案上傳不在 V1；避免不完整刪除留下子集合。

## 真實環境驗收清單

1. 管理員建立 A、B 兩個空間；給帳號 E 在 A 編輯者，帳號 V 在 A 檢視者。
2. E、V 用不同瀏覽器登入；兩人都能看 A，不能看 B，即使直接輸入 B 網址也不能讀取。
3. E 新增、修改行程，V 不刷新即可看到；V 不能寫入或刪除。
4. 兩個編輯者同時開啟同筆行程；一人先儲存，另一人儲存時應收到衝突，草稿仍在。
5. 管理員撤銷 E 權限，E 的畫面清除，新的讀寫被規則拒絕。
6. 未核准 Google 帳號能登入，但沒有工作空間也無法透過網址讀取資料。
7. 斷網時不得顯示已成功儲存；恢復連線後再儲存。取消草稿、重新整理及重新登入行為符合預期。
8. 手機操作表單、登入彈出視窗、返回首頁；確認真實 Pages 專案子路徑正常。
9. 確認 Firestore 規則已部署，並通過 `npm run test:rules`；使用兩個真實 Google 帳號完成以上測試後再正式分享。

## 新增工具

沿用 core.js 的登入與角色觀察；定義新工具自己的 records 格式與規則驗證，再加入首頁卡片、工具頁及對應工作空間建立流程。不要把使用者提供的任意 HTML 直接以管理員身分載入；新工具程式碼須由專案維護者審閱。請保持相對路徑以支援 GitHub Pages 子目錄。
